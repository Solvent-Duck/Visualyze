# Approved placement plan: acceptance ledger

This ledger tracks the user's approved **Visualyze placement system: compact, understandable architecture at every scale** plan. It does not replace or reduce that plan. The engine remains experimental until its correctness, performance and comprehension gates pass. A production source inventory has been ingested and displayed, but that milestone alone does not complete the plan.

Evidence is scoped: a unit test proves its cases; a native screenshot proves a particular rendered view; a dated benchmark proves its recorded implementation and conditions. Historical fixtures used during later development are development evidence, even if originally described as held out. Missing or indirect evidence is not a pass. Current measurements and reproduction commands live in [placement validation](placement-validation.md); implementation boundaries live in [ADR 0006](decisions/0006-placement-engine.md).

## Validation and release

| Gate | Evidence required to close it |
| --- | --- |
| Semantic identity, legal geometry/ports, no unrelated penetration/overlap, truthful auth/passage/shared/cyclic/parallel/disconnected behavior | Retain the current invariant tests and independent raw-reference oracle; extend them for new presentation transforms or changed algorithms. |
| Input-order determinism, conflicting pins, cancellation, stale revisions, incomplete detail and cache eviction | Current targeted tests and native proofs are scoped evidence; rerun affected checks after implementation changes. |
| Median route/packing improvement over credible baselines, no hard correctness failures | Freeze the quality/profile/corpus first; compare identical projections and report route/packing tradeoffs separately. The original-renderer adapter reports diagnostic invalid rows separately; integrate a calibrated, frozen comparative release decision without treating those rows as valid winners. |
| Representative CRUD, SaaS, event-driven, multi-region, many-table, deep-code and public architectures | Existing fixtures cover many of these cases. Record expansion/page cases and provenance in the evaluation manifest; retain pinned Online Boutique and DeathStarBench revisions. |
| Production complexity ingestion/display | Pinned Bevy: 27,117 entities, 44,019 relations; syntax-v2 and legacy imports/native navigation are measured. This proves a source inventory, not full runtime architecture extraction. |
| Synthetic AI and monorepo scale, stated assumptions | Declared distributed AI and synthetic hierarchy inputs exist. Do not present them as OpenAI's actual stack or claim unsupported dense-graph performance. |
| Less-experienced and experienced developer comprehension sessions with current scene and conventional layered controls | Still unrun. Record task accuracy/time, navigation errors and confidence for locating, tracing, auth coverage, table inspection, cross-system dependencies and update recognition. Pre-register evaluation decisions before collecting results. |
| Default promotion only after geometry, performance and comprehension gates; previous renderer retained; cache versioning and accepted overrides preserved | Previous renderer remains the default for snapshots. Keep it that way until every gate is supported. A lower provisional score or successful million-record import is insufficient. |

The plan remains active. Remaining work includes broader topology and cross-context semantics, general protected-group topology repair, broader cross-frame recovery and routing-space enlargement, stronger reproducible comparison, instrumented performance/input verification, and human evaluation. Native composition, independent interior caches, repair and current-view persistence have scoped evidence; they do not close the broader gates. Do not collapse those into a single “waiting for feedback” blocker while independent engineering work remains.
